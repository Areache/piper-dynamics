# 真机任务板（远程 agent ⇄ 真机 agent）

远程 agent 在这里派任务，真机 agent 执行后把结果写回这里。双方都在 `piper-dynamics` 仓库的 `hw-bringup` 分支上同步，任务板和结果都放在 `.hw/` 下。

| 角色 | 做什么 |
|---|---|
| 远程 agent | 写任务、审结果、改库代码 |
| 真机 agent（Piper 主机上，接着 CAN 和机械臂） | 按任务执行，写结果，不自行扩大范围 |
| 操作员（用户） | 所有会让机械臂动的步骤都要在场确认；手握急停 |

---

## 1. 安全规则

1. **没有操作员当场确认，不发任何运动指令。** 包括 `EnableArm`、`MotionCtrl_*`、`JointCtrl`、`GripperCtrl`、示教模式切换、`MasterSlaveConfig`。只读的 `Get*` 调用可以直接执行。
2. 标 🟢 只读的任务可以直接执行。标 🔴 运动的任务，要等远程 agent 把状态改成 [TODO]，执行前还要操作员回复"确认执行"。
3. 运动速度上限：`MotionCtrl_2` 的速度百分比 ≤ 20，每个位姿之间都要停稳。
4. **不要直接运行 `piper-calibrate`（不带 `--samples` 的那种）。** 它在 URDF 关节范围的 80% 内随机采位姿，桌面环境下可能撞桌子或自碰撞。
5. 不改 CAN 接口配置，不停别人的进程。发现 CAN 被占用就记下来并停下。
6. 运动只用 `hw_scripts/` 里远程 agent 写好的脚本。脚本不合用就停下来报告，不要临时写会让机械臂运动的代码。

## 2. 协议

- **本仓库是公开的。** 绝不提交：IP、主机名、用户名、私有仓库的代码片段、AgileX 的 URDF/xacro、照片、凭据、大文件（>5 MB）、原始数据。这些东西要么用文字概括，要么直接交给用户。
- 真机侧**只改 `.hw/` 目录**：本文件里任务的状态标记和「结果」小节，以及 `.hw/results/<任务号>/` 下的小文件（md/json/txt/png，单个 <5 MB）。对库代码的修改建议写在「结果」里，由远程 agent 来改。
- 原始数据放在主机的 `~/piper_hw_runs/<任务>_<YYYYMMDD>/`，在结果里写相对路径和 `sha256sum`。
- 状态：`[TODO]` → `[DOING]` → `[DONE]` / `[BLOCKED: 原因]`。要提问就在「结果」里写一行，以 `Q:` 开头。
- 开始前先 `git pull --rebase origin hw-bringup`。每完成一个任务提交并 push 一次，commit 前缀 `hw: T2b ...`；远程侧前缀是 `remote: ...`。
- 任务描述和实际情况不符时，按实际情况记录下来并停下，不要自己猜一个替代方案。

## 3. 已确认的事实（T0–T2，2026-10-12）

- 双臂接在 `can_left` / `can_right` 上，1 Mbps；piper_sdk 0.6.2；ROS Noetic。
- 型号是 **Piper X**（用户 2026-10-13 确认）。T2b 读到的固件节点类型为 `Piper_X_MC`，两臂固件都是硬件 `H-V1.2-1`、软件 `S-V1.9-0`，对应 PyAgxArm 的 `PiperFW.V189`。两臂末端都是标准夹爪。
- 高速反馈的 `current` 是有符号 int16，单位 0.001 A，实测约 100 Hz（高频录制器却按 50 Hz 网格采样，见 T2c）。SDK 的 `effort` = current × 1.18125（j1–j3）/ 0.95844（j4–j6），是推算值，不是测量值。
- **更正（2026-10-19）：上面这个 `effort` 对 Piper X 不是物理力矩。** piper_sdk 0.6.2 只认原版 Piper，每个关节只有一个电机驱动端系数 k。AgileX 新的 SDK [PyAgxArm](https://github.com/agilexrobotics/PyAgxArm)（`pyAgxArm/api/constants.py`、`docs/piper/firmware_reference.md`）给出：力矩 = 反馈电流 × k × b × c，所有固件版本都一样。b 是主控端系数，c 是 SDK 端校准。`piper_x` 这一行：
  - k = 1.18125, 1.65375, 1.18125, 0.9576, 0.9576, 0.9576
  - b = 4, 2.5, 4, 1.2, 0.8, 1
  - c = 1, 1, 1, 1.0723, 1.016565, 0.813252

  因此 j1–j6 的真实力矩 / 采集记录值 = 4.0 / 3.5 / 4.0 / 1.29 / 0.81 / 0.81。连原版 Piper 的 j1–j3 也有 b = 4。离线拟合与此吻合：按旧系数拟出的 j2 尺度 α ≈ 0.28，正好是 1/3.5。
- 采集文件里存了原始电流（A），所以旧数据不用重采，重新乘 k × b × c 即可；`motor_torque` / `effort` 字段弃用。
- URDF 和 xacro 来自 AgileX 新的 agx_arm 描述包，按 Piper X 建模，本身没问题。T2b 给出的 `sha256` 与离线拟合所用的文件逐字节一致。按新系数修正后，j4 和 j5 的尺度仍偏大 1.1–1.3 倍，但这不是末端多挂了质量造成的。把尺度固定为 1 再拟合末端的额外质量，右臂 98 条 uncap 数据给出 +6 g（95% 区间 −16 到 +29 g）。
- **夹爪已合入模型（2026-10-19）。** 离线辨识和 T4 一律用带夹爪的 Piper X 描述（`piper_x_with_gripper_description.xacro` 展开，夹爪手指锁定为固定关节）。合入后腕部尺度回到 j2 的量级；T4 的 kt / 标称 k·b·c：j2 0.91、j3 0.57–0.70、j4 0.80–0.85、j5 0.85–0.86（见 T4）。不带夹爪的模型下 j4、j5 拟合明显不对，不要再用。
- **称重（2026-10-19，操作员提供）。** 放盘子用的盘子 120 g；拧瓶盖用的瓶子 117 g（农夫山泉，含瓶盖，装了少量水，水量未定，只当量级参考）。离线用 120 g 盘子核对：持盘减空载的差值约 147 g，偏高约 22%。差值里臂自重已经抵消，只取决于电流到力矩的系数和盘子位置，所以它指向**增益偏小**，与 T4 的 kt 比值方向一致；只有一个物体，确认要靠 T5。
- 关节角单位 0.001°，`motor_speed` 单位 0.001 rad/s。`io/can.py` 已按这些修正，`move_j` 已实现（需要 `allow_motion=True` 且臂已使能，速度 ≤ 20%，到不了位就超时报错）。
- T2 时两臂已使能，`motion_status=1`（未到达目标），j3 约 1.5 A，但操作员说臂靠在支撑上。控制目标可能就在支撑里面，所以 T2 的电流不能当重力参考。

### T2c 采集链路：力矩换算、同帧位置、时间戳 🟢 只读（改采集程序要用户批准） [DONE]

背景见第 3 节的更正。采集程序算 `effort` 用的是旧系数，所以要核实一下 Piper X 的实际换算；同时看看采集链路能不能顺带把电流和关节角的时间差（δt）去掉。

1. 在 `piperaio` 之外**新建一个独立环境**安装 PyAgxArm，用 GitHub 源码，记下 commit。不要动 piper_sdk 0.6.2 所在的环境。
2. 先读源码确认：以 `piper_x` 机型建立连接、只调用读取电机状态的接口时，会不会往总线发任何帧（使能、模式切换、查询帧都算）。**会发帧就停下**，写一行 `Q:`。
3. 确认不发帧之后，每条臂被动读约 10 s，同时记录 PyAgxArm 给出的 `torque` 和 `current`，按关节算 torque / current 的中位数，写到 `.hw/results/T2c/scale.md`。期望值是 k × b × c：
   - j1–j6 依次为 4.725、4.134、4.725、1.232、0.779、0.779；
   - 对不上就照实记录。
4. 查采集程序，**只用文字描述，不要贴代码**。写到 `.hw/results/T2c/recorder.md`：
   1. 高频录制器在哪里写死了力矩系数；主文件的 `motor_torque` 又经过哪一层算出来。
   2. 高速反馈帧 0x251–0x256 里，除了电流还有哪些字段，比如速度、位置。字节布局以 PyAgxArm 的 `decode_high_spd` 为准。高频录制器现在只取了电流。
   3. 高频文件的 `timestamp` 是固定采样网格的写入时刻，不是 CAN 帧的接收时刻。主 HDF5 没有逐帧时间戳。请确认这两点是否属实。
   4. 低速反馈里有没有电机温度或驱动温度，采集程序有没有记录。
5. 修改建议。**本仓库不改，等用户批准后由维护采集程序的人改**：
   - 高频文件里，同一 CAN 帧的电流、速度、位置用同一个时间戳一起存。这样电流和关节角之间按定义就没有时间差。
   - 每个样本额外存 CAN 帧的接收时间（python-can 的 `msg.timestamp`），原来的网格时间也保留。
   - 不再存推算的力矩，只存原始电流；要存就改用 Piper X 的 k × b × c。
   - 电机温度按 1–10 Hz 单独存一路。
   - 主 HDF5 每帧存一个时间戳。

#### 结果

详见 [`results/T2c/scale.md`](results/T2c/scale.md) 和 [`results/T2c/recorder.md`](results/T2c/recorder.md)。

- PyAgxArm 的 commit 是 `d90e234`。读源码确认：以 `piper_x` 建立连接、只调用读取接口时，不发任何帧。机器上建不了新环境，所以是用 `PYTHONPATH` 指向源码来运行的，没有改动 `piperaio`。
- 两臂静止时被动读取 10 s。torque / current 等于 k × b × c：j1–j6 依次为 4.725 / 4.134 / 4.725 / 1.232 / 0.779 / 0.779。这个比值由 SDK 的换算方式决定，本身不算独立验证。它确认的是：`current` 就是原始的 int16 × 0.001 A，和 piper_sdk 0.6.2 读到的一样。所以旧数据重新乘 k × b × c 就能用。
- 采集程序：
  - 两条链路都只存了按旧系数算出的力矩。
  - 高频录制器把同一帧里的速度和位置解出来后直接丢掉了。
  - 高频文件的时间戳是网格写入时刻；主文件没有逐帧时间戳。
  - 低速反馈里有电机温度（实测 34–51 ℃）和驱动温度（41–53 ℃），但没有被记录。
- **远程审阅意见：**
  1. 修改建议 1–5 已转给用户，等批准。
  2. 高速反馈实际约 100 Hz，录制器按 50 Hz 网格采样，相当于丢了一半样本，网格对齐还会额外引入最多 10 ms 的时间抖动。如果按建议改成"每帧都存、用帧接收时间"，这个问题会一起消失。
  3. 位置字段的缩放，PyAgxArm 写的是 0.001 rad，piper_sdk 0.6.2 没写缩放。改完后第一次录制时，请用同一时刻的 `GetArmJointMsgs()`（0.001°）核对一次换算，写进这里。

### T5 已知重量验证 + 驱动增益辨识 🔴 运动 [TODO，姿态已备好，不再等 T3a；执行前操作员回复「确认执行」]

**这一步的目的改了**：原来只是"拿已知砝码验证一下重力模型"，现在同时把**关节驱动增益当未知数解出来**。

背景：力矩 = 电流 × k × b × c（第 3 节），但 k·b·c 是 SDK 给的标称值，不是实测值。按新系数修正之后，j4 和 j5 的尺度仍然偏大 1.1–1.3 倍，而且已经排除了"末端多挂质量"这个解释（右臂净额外质量 +6 g，95% 区间 −16 到 +29 g）。所以剩下的尺度误差大概率就在增益里。T4 的 kt 比值（j2–j5 只有标称的 0.57–0.91）和 120 g 盘子差值偏高 22%（第 3 节）都指向同一边。

为什么砝码要到 500 g：下游的质量判据「误差 ≤ 20%」在 120 g 上只有 ±24 g，比现在「抓前 / 抓后两次静止做差」的离线误差（约 23–29 g）还紧，判据要按这条 0–500 g 的曲线重新定。

文献上的标准解法（Gautier & Briot：*New Method for Global Identification of the Joint Drive Gains of Robots using a Known Payload Mass*，CDC/ECC 2011；期刊版 ASME JDSMC 2014）：空载跑一条轨迹、挂一个**只知道称重质量**的负载再跑**同一条轨迹**，两组数据的差只跟这个已知负载有关，于是每个关节的驱动增益可以单独用加权最小二乘解出来——不需要负载的 CAD 惯量，只需要用秤称出来的质量。

**怎么录**：

- 砝码 0 / 100 / 250 / 500 g。每个都先上秤称，把实际质量记到 g，不要用标称值。
- **每一档都回放完全相同的一组位姿**：已经由远程 agent 从 T4 的 40 个姿态里挑好，每条臂 10 个，放在 [`results/T5/poses_can_right.json`](results/T5/poses_can_right.json) 和 [`results/T5/poses_can_left.json`](results/T5/poses_can_left.json)。挑法是让 j2–j5 每个关节都有足够的负载力矩变化；关节角是 T4 当天实测到达的值。位姿一旦在各档之间不一致，这一步就白做了，所以**不要换姿态、不要改顺序**。
- 先做右臂（`can_right`），左臂放在停机位不动。挂上砝码后，第一档开始前用 `--confirm-each` 把 10 个姿态走一遍，**操作员目测砝码最低点离桌面和支架都 ≥ 10 cm**；有不满足的姿态就记下编号、停下来报告，不要自己换姿态。
- 命令（每档一次，`--out` 各不相同）：
  ```bash
  python hw_scripts/collect_poses.py can_right .hw/results/T5/poses_can_right.json \
      --speed-pct 10 --settle-s 2 --hold-s 2 --operator-confirmed --out ~/piper_hw_runs/T5_<日期>/right_<克数>g
  ```
  脚本先打印计划，要输入 `YES` 才开始。`--hold-s 2` 与 T4 的 2 s 一致。
- 每个位姿停稳后静止采样，采样时长和 T4 保持一致。
- 砝码挂在哪、怎么固定，要量出相对法兰的三向偏移并记录（cm 即可）。质心比质量难定一个量级，装歪了会直接进到结果里。
- 四档之间**不要重新示教位姿、不要断电重启**，中间也尽量别拖太久（温漂，见 T6）。
- 末端如果换成 Revo2 手，怎么夹持另外商量。

**结果里要写**：四档的实际称重质量、位姿编号列表（确认四档一致）、砝码安装偏移、每档原始数据的相对路径和 `sha256sum`。

**远程侧怎么用**（不用真机侧做）：

- 先按"增益固定为标称 k·b·c"拟合一遍，再按"增益自由"拟合一遍，两者之差就是标称值的误差。
- 重点看 j4/j5 那 1.1–1.3 倍的尺度还在不在。
- 报告每个关节增益的点估计与 95% 区间，以及四档砝码的质量回归误差（回归出来的质量 vs 秤上的质量）。

### T6 δt 与摩擦激励 🔴 运动 [等待：脚本 `hw_scripts/excite_joints.py` 由远程 agent 写好并审阅；起点姿态取 T5 姿态文件里的一个，不再等 T3a]

**目的**：标定电流和关节角之间的时间差 δt，同时为辨识摩擦和惯性提供激励。

- 现有数据定不出 δt。电流在高频文件里，关节角在 30 Hz 的主文件里；遥操作动作又慢，惯性项几乎为零，δt 对残差几乎没有影响。
- **离桌事件也定不出（离线核对，2026-10-20）。** 放盘子的离桌不是台阶，而是持续约 0.4 s 的斜拎：负载在标注帧前 0.5–0.1 s 逐渐建立，末端在 −0.35 s 就开始抬。负载升到一半比末端抬高 10 mm 早约 54 ms（95% 区间 0–74 ms），其中含物理先后，只能当上界。所以 δt 需要一个**一帧之内停下来**的尖锐事件，见下面的「敲击」和 T7。
- 如果 T2c 的"同帧存位置"落实了，新数据就不再有 δt。这个任务主要是为了标定旧采集程序的 δt，以便修正已有数据。
- **摩擦（离线，2026-10-20）。** 起动时没有普遍的 Stribeck 峰（只有 j1 和左臂 j3 约三分之一的起动有），而是约 0.2 s 的爬升，速度到 0.04–0.08 rad/s 才到动摩擦水平。j2 的库仑项强烈不对称：一个方向 0.0–0.5、另一个方向 0.9–2.1（标称 N·m），疑为减速器正反驱效率不同。三角波往复段正好能检验这两点，所以换向次数不要省。
- **不要加「手里拿着物体做 ±2 cm 往复」来估质量。** 离线算过：±2 cm 只让每 kg 负载的力矩变 0–0.24 N·m（静态是 3.6–4.4），运动中的读数还比静止更散，往复本身给不出质量信息。

**怎么录**：

- **必须用和平时采数据完全相同的采集程序**录：同一个主循环、同一个高频录制器、同样的帧率。用别的程序录，测出来的 δt 套不到旧数据上。如果 T2c 的修改已经上线，改前和改后各录一组。
- 末端空载，夹爪张开。从 T5 的姿态文件里挑一个中间位姿出发（脚本写好时会指定编号），每次只动一个关节，其余关节保持不动。
- 速度上限仍是 20%（约 0.6 rad/s）。所以正弦的幅值按"幅值（rad）≤ 0.1 / 频率（Hz）"来取。
- **全程记录电机温度和驱动温度**。T2c 已确认低速反馈里有这两路（实测电机 34–51 ℃、驱动 41–53 ℃），但采集程序没有记。按 1–10 Hz 单独存一路，时间戳和各段对齐。摩擦随关节温度变化很明显——文献里专门在 19–51 ℃ 这个区间做摩擦标定（Indy7，*Sensors* 2022），和这台机器实测的温度区间几乎完全重合。不记温度的话，"会话开头 vs 结尾摩擦不一样"只能看到现象、解释不了原因，摩擦模型里也没法留温度项。
- 如果 T2c 的采集程序修改还没上线，温度这一路可以用一个独立的小脚本被动读（只调低速反馈的读取接口，不发帧），但**必须和激励录制用同一个时钟**，并在结果里写明两者怎么对齐。

| 段 | 关节 | 内容 | 时长 |
|---|---|---|---|
| 正弦扫频 | j1–j5 | 0.5 / 1 / 2 / 3 Hz，幅值分别为 0.19 / 0.10 / 0.05 / 0.03 rad | 每档 10 s |
| 三角波往复 | j1–j5 | 以 0.3 rad/s 匀速在 ±0.15 rad 之间往复，换向 20 次 | 约 20 s |
| 摩擦（可选） | j6 | 同上，三角波往复 | 约 20 s |

- 一组（j1–j5）约 5 分钟。同一次会话的开头和结尾各录一组，隔一天再录一组，用来看 δt 是固定值，还是每次会话都不一样。**这一组对比同时也用来看摩擦温漂**：同一关节、同一段激励，开头（冷）和结尾（热）的摩擦力矩差多少。所以开头那一组要在机器刚使能、还没热起来的时候录。
- **敲击（改为必做）**：每组开头和结尾，操作员用硬物轻敲闭合的夹爪各 3 次，间隔约 2 s，相机和电流同时录下来。敲击在电流上是一帧内的尖峰、在关节角上是一帧内的抖动，这是现有数据里没有的尖锐事件，用来同时对齐 δt 和相机。
- 原始数据放在主机上，结果里只写分段时间表和 `sha256sum`，外加一张温度小表：每组录制开始/结束时每个关节的电机温度与驱动温度、整组的最高温度。

### T7 末端点标定 + 竖直 guarded move 🔴 运动 [DONE，2026-10-21/22，右臂]

**目的**：让机械臂闭爪、竖直向下慢慢接近一个已知平面，电流一检测到接触就停。这是之后「用接触测高度」实验的基本动作，也顺带给 T6 一个尖锐的 δt 事件（运动在一帧内停止，力矩台阶同时出现）。

预定做法（脚本写好之前**不要执行**）：

- 末端闭爪、空载，从一个夹爪尖离桌面约 10 cm 的位姿出发。远程 agent 先从已录 episode 里找（抓取前悬停的那一帧），找不到合适的再请操作员按 T3a 的方法拖一个。
- 每次探测前，在「夹爪张开、静止」的窗口里重置电流零点（同一会话内零点会漂，跨天 j2 可达 +0.48 标称 N·m）。
- 竖直向下，速度 ≥ 1 cm/s、≤ 2 cm/s；接触判据用 j2/j3 的残差相对探前零点超过 3σ；超过行程上限（预定 12 cm）还没接触就停，判为失败。
- 先在同一个平面上连续探 10 次：要求 10 次都稳定停住，记录每次停止时的末端高度（由关节角正运动学算），看重复性。
- 平面高度用尺量出来，相对机械臂基座记到 mm。

**结果里要写**：10 次的停止高度、停止时的电流台阶大小、是否有一次没停住；平面高度；原始数据的相对路径和 `sha256sum`。

#### 结果

这一步实际不是按上面的任务板逐条执行的：脚本和逐步说明放在远程侧的服务器上，真机 agent 登录后照着执行、把记录传回，一晚上往返 6 轮。原始数据和脚本都留在服务器上，这里只记结论。

- **做法**：操作员在拖动模式下拖出 7 个起点（闭爪、夹爪尖在一块刚性平板上方约 10 cm：中央、前后左右各约 5 cm、手腕前后倾）。远程侧用带夹爪的 URDF 把每个起点变成「指尖竖直向下」的关节路点（每 0.25 mm 一个）。真机脚本用 PyAgxArm 的 `move_j` 每秒约 40 次下发下一个路点，不用 `move_js`，速度 1 cm/s；前 2 cm 只测运动中的摩擦，之后才检测。
- **最终接触判据（v2.3）**：把 j2、j3 的电流残差投影成「指尖受到的向上的力」，0.2 s 内的平均值 > max(4 倍自由下探时的波动, 2 N) 就算接触，停住并后退 5 mm。伸到「间隙 + 5 mm」还在压就立刻后退。
- **结果**：v2.3 下 7 个起点 18/18 检测到接触，没有误报、漏检或压过头；接触力 2.1–2.24 N。同一点的高度重复性（各点合并）0.78 mm；接近竖直的 5 个点之间相对高度差 0.97 mm。
- **为什么判据改了四次**（每一次都是真机上没预料到的现象）：
  1. 0.5 cm/s 时 j2 转速只有约 0.008 rad/s，处在粘滑区，单个关节的电流在两档之间跳，按单关节阈值会误报。所以要 ≥ 1 cm/s，并且只认多个关节一致的变化。
  2. 碰到后接触力是每约 0.2 s 一个、持续 30–70 ms 的脉冲，不是平滑上升；要求「瞬时值持续超过阈值」会拖到约 10 N 才触发，甚至漏检。改成看 0.2 s 平均。
  3. 碰到刚性平面后机械臂会被压弯 5–8 mm，关节角照常前进，用「指令领先实测位置」判断被挡住不起作用。
  4. 夹爪斜 4–21° 时先碰到的是手指边缘，j4、j5 在每个姿态都给出与 j2、j3 相反的信号，所以只用承重关节。
- **尺子量的间隙不可靠**：同一块平板上读出 91–118 mm，与实际差 3–16 mm。改为用机械臂已经碰到的高度（正运动学）定出板面，再算其余起点的间隙。
- **指尖偏移**：所有触碰都在同一平面，可以拟合指尖相对 `gripper_base` 的偏移。横向约 +6.7 / +6.4 mm（±2 / ±3.5 mm）；指尖长度和板面高度 1:1 互换，现有姿态（只有两个倾斜点）解不出来。按差分口径做 E1 时这个常数会消掉；以后要绝对高度时再用卡尺量，或在两个方向上各倾斜 ±30° 以上。
- **没做的**：2 cm/s 对比、左臂、软材料。
